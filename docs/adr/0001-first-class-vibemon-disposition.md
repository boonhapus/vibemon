# First-class Vibemon disposition

Vibemon disposition is persisted as a domain fact rather than inferred only from nullable trainer ownership. Playable disposition is exactly **Owned** or **Wild**; **Expired** is a non-playable tombstone disposition for wild Vibemon that leave the game through expiration and is terminal for normal gameplay transitions. Generation-in-progress remains service/workflow state, not a Vibemon disposition. This preserves the distinction between a Vibemon that is intentionally **Wild** and a Vibemon whose trainer assignment is absent for incidental reasons, and it gives **Adoption**, **Release**, candidate rejection, and expiration explicit domain transitions without overloading lifecycle state. Adoption is the transition to **Owned** whether it comes from accepting a generated candidate or a future wild catching mechanic; adoption source records that origin, and adopting a wild Vibemon removes it from global wild encounter eligibility immediately. Release preserves progression, learned moves, history, and core manifestation assets. Rejected candidates become **Wild** rather than being discarded, because their provider fetch, christening, reference image, and battle cry costs have already produced known-good Vibemon from real user data.
