# Trainer candidate generation uses daily sequential credits

Trainers receive three generation credits per day for candidate generation, but generation jobs run sequentially rather than in parallel. A trainer may have multiple unresolved candidates under review up to their available daily generation credits, but only one candidate generation job may run at a time. A credit hold is placed while generation runs to prevent parallel requests, then the credit is consumed only when a christened candidate is successfully shown; failed generation releases the hold without spending the credit. Adoption of a shown candidate is free and does not consume another generation credit. This still lets a trainer see up to three candidates per day while keeping external generation cost and concurrency under control; rejected candidates enter the wild pool so spent preview work remains useful.
