# P6-T1 — Stretch Goals (PvP, Collection, Share Card, New Providers)

**Phase:** 6 — Stretch Goals
**Dependencies:** P5-T3 (all core features complete)
**Depends on this:** None

---

## Objective

Optional enhancements that extend the game beyond the single-player MVP. Each sub-task is independent and can be picked up in any order.

---

## Sub-task A: PvP via Shared Seed URL

**Goal:** Two players share a link; their Vibemons fight with a deterministic battle RNG derived from the URL seed.

- Generate a shareable URL containing both player seeds (e.g. `/pvp?p1={seed}&p2={seed}`)
- Recipient generates their own Vibemon, then the battle plays out with a shared RNG seed so both players see the same result
- Battle RNG seeded from `hash(p1_seed + p2_seed)` for determinism
- No server needed — both clients independently compute the same battle
- Share via Web Share API or copy-to-clipboard

---

## Sub-task B: Local Collection (Pokédex)

**Goal:** `localStorage`-backed collection of all Vibemons a player has generated.

- After each battle, save the player's `VibemonPayload` to a local collection
- Collection screen at `/collection` showing a grid of past Vibemons as mini SVG thumbnails
- Tap to view full stats, visual DNA, flavour text, and battle history (win/loss)
- De-duplicate by `uid`; update if the same Vibemon is generated again with different stats (drift)
- Import/export collection as JSON

---

## Sub-task C: Post-Battle Share Card

**Goal:** Generate a PNG image summarising the battle result that can be shared on social media.

- After victory/defeat, offer a "Share" button
- Render a canvas element with:
  - Player Vibemon SVG (rasterised to canvas)
  - Name, element, key stats
  - Battle result (Victory/Defeat)
  - Turn count, remaining HP
  - "Generated by Vibemon" watermark
- `canvas.toBlob()` → download as PNG or share via Web Share API
- Dimensions optimised for social media (1200×630 or 1080×1080)

---

## Sub-task D: Additional Providers (Strava, Steam)

**Goal:** Add new data sources following the existing plugin architecture.

**Strava:**
- OAuth2 flow (requires backend proxy like GitHub)
- Fetch recent activities: distance, pace, heart rate, activity type
- Map: distance → `hp_factor`, pace → `speed_factor`, heart rate → `attack_factor`
- Activity type votes: running → Electric, cycling → Ground, swimming → Water

**Steam:**
- Steam Web API (API key required)
- Fetch owned games, recent playtime, genre tags
- Map: total playtime → `hp_factor`, genre diversity → `sp_attack_factor`, recent hours → `speed_factor`
- Genre votes: action → Fire, strategy → Psychic, horror → Dark

Each new provider: one new file in `backend/app/providers/`, one line in `PROVIDER_REGISTRY`, one OAuth flow if needed.

## Acceptance Criteria (per sub-task)

- **A:** Two players with the shared URL see identical battle outcomes
- **B:** Collection persists across browser sessions and displays correctly
- **C:** Share card generates a downloadable PNG with accurate battle info
- **D:** New providers produce valid `SourceData` and merge correctly with existing providers
